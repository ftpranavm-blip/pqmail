Learn — the ideas behind PQMail

What is encryption?

Scrambling information so only someone with the right key can read it. Modern encryption is mathematically strong — the security lives in the keys, not in secrecy of the method.

Public vs private keys

Your public key is like an open padlock: anyone can use it to lock (encrypt) a message to you. Your private key is the only key that opens it. Public keys are shared freely; private keys never leave your device.

What is post-quantum cryptography (PQC)?

Cryptographic algorithms designed to resist attacks by future large-scale quantum computers. Today's RSA/ECC would fall to such machines (Shor's algorithm); PQC is built on different math — like lattices — believed hard even for quantum computers. PQC runs on normal computers and networks.

What is ML-KEM? (FIPS 203)

The NIST-standardized key encapsulation mechanism based on module lattices. One party encapsulates a shared secret to the recipient's public key; only the recipient's private key can decapsulate it. PQMail uses ML-KEM-768 (192-bit security strength). It was standardized from CRYSTALS-Kyber — "Kyber768" is the predecessor implementation name.

Why a hybrid exchange? (X25519 + ML-KEM)

ML-KEM is new and X25519 is old: a future quantum computer breaks X25519, but a surprise weakness in the young lattice scheme is also possible. PQMail runs both and mixes the two shared secrets into one key (the same idea as TLS X25519MLKEM768), so an attacker must break both to read a message. See the live benchmarks for the cost.

What is ML-DSA? (FIPS 204)

The NIST-standardized lattice-based digital signature. A signature proves who sent data and that it was not changed. PQMail uses ML-DSA-65, standardized from CRYSTALS-Dilithium ("Dilithium3" is the predecessor name).

What is AES-GCM?

A fast, widely used authenticated encryption scheme: it encrypts (confidentiality) and authenticates (integrity) at once. Any modification of the ciphertext — even one bit — makes decryption fail loudly. PQMail uses AES-256-GCM with a fresh random nonce for every message.

What is a digital signature?

Signing data with your private key creates a verifiable proof that anyone with your public key can check. If verification fails, the data was altered or did not come from you. PQMail signs the whole envelope — metadata included.

What is end-to-end encryption (E2EE)?

Encryption where only the endpoints (sender and recipient) can read the message. Servers, network operators and eavesdroppers see only ciphertext. In PQMail the encryption and decryption happen inside the app — never on a server.

What is QKD / BB84?

Quantum Key Distribution exchanges keys using quantum states (photons). In the BB84 protocol Alice encodes random bits in randomly chosen bases; Bob measures in random bases. An eavesdropper's measurements unavoidably disturb the states, creating detectable errors. Real QKD needs quantum hardware — PQMail includes an educational simulation only, and QKD is not required for PQC.

Why hybrid ML-KEM + AES?

ML-KEM establishes a shared secret but doesn't encrypt arbitrary data. So PQMail uses it to establish the key, then a fast symmetric cipher (AES-256-GCM) encrypts the actual message — the same hybrid pattern used by TLS 1.3's post-quantum mode (X25519MLKEM768).

What is HKDF?

A standard key-derivation function (RFC 5869) that turns the KEM's raw shared secret into a proper AES-256 key, mixing in a random salt so every message has a unique key even between the same two people.

Honest terminology

PQMail says "designed to resist known quantum attacks" — never "quantum-proof". PQC security rests on computational assumptions; QKD security rests on physics but needs hardware. This project uses the former for real protection and simulates the latter for learning.
